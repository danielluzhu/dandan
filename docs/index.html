How it works

Partiful sends x-frame-options: SAMEORIGIN, so its pages cannot be put in an iframe. Instead, dandan reads the __NEXT_DATA__ JSON that every Partiful event page ships and caches the title, date, cover image, location and RSVP count in SQLite — then renders its own cards and links out to the real RSVP page.

Syncs itself

A background loop refreshes every event that is still ahead of us, hourly, so a date moved on Partiful shows up here without anyone pressing a button. This page republishes itself on the same principle: nightly, and only when something actually changed.

Up next & the archive

Scheduled events sit at the top, soonest first. Six hours after an event starts it moves itself into the archive, grouped by year — the same lists you scrolled through above.

The list

People leave a name, an Instagram handle and the series they'd come to. The list is private, searchable and sortable, and mirrors to a spreadsheet you can open in Excel.

Nothing leaves the machine

Contacts live in a local SQLite file that is never committed. /list and /admin sit behind one password; the public form has a honeypot and a rate limit.

Built on

  • BunThe HTTP server, the test-free small-project runtime, and bun:sqlite.
  • SQLiteOne file holding events and contacts. WAL mode, no ORM.
  • No frameworkServer-rendered HTML from template literals, one stylesheet, one small script.
  • PartifulStill where the RSVPs happen — this is the front door, not a replacement.

Running it

# set ADMIN_PASSWORD and SESSION_SECRET
cp .env.example .env

bun run start          # http://localhost:4321
bun run add https://partiful.com/e/xxxxxxxx
bun run sync           # refresh the cache by hand
